# 产品使用指南

*从编辑、组织到发布，系统掌握 HappyDays非官方文档的核心工作流。*

HappyDays非官方文档的核心只有一件事：**让团队知识在被需要的时候，出现在正确的人面前**。这篇指南覆盖从写下一段文字，到让它持续被使用的完整路径。

## 文档的生命周期

每篇文档都会经历草稿、发布和归档三个阶段。理解它们，可以避免「写了没人看」和「过期内容被误用」。

| 状态 | 谁可以查看 | 适合放什么 |
| --- | --- | --- |
| **草稿** | 作者与协作者 | 尚未验证的想法、半成品、个人笔记 |
| **已发布** | 按可见范围决定 | 可被依赖的流程、说明、决策记录 |
| **已归档** | 保留可查，默认不展示 | 已被替代的方案、阶段性项目材料 |

当一篇文档被新版本取代时，优先**归档旧文档并在开头加上指向新版本的链接**，而不是直接删除。历史链接不应该变成死路。

## 编辑器：像搭积木一样写作

编辑器以「块」为基本单位。一段文字、一个标题、一张表格、一段代码，都是可以独立移动和变换的块。

### 斜杠命令

在空行输入 `/`，即可打开内容块菜单。常用命令包括 `/h2`、`/table`、`/code`、`/callout` 和 `/divider`。继续输入关键词可以快速筛选。

### 拖拽与分栏

将鼠标移到块左侧，拖动六点手柄即可调整顺序；把一张图片拖到另一张图片旁边，会自动形成分栏。分栏适合对比方案，不建议用来做复杂页面排版。

### 粘贴与导入

从 Word、Notion 或网页粘贴内容时，编辑器会尽量保留标题、列表和表格结构。复杂样式会被清理，这通常是一件好事：**内容应该适应阅读，而不是适应来源。**

> [!TIP]
> **写作时先关闭「排版模式」**
>
> 先把信息写完整，再统一调整标题层级和强调。过早纠结样式，通常会让内容变得空泛。

## 组织你的知识库

### 用目录树建立骨架

目录树回答「我在哪、接下来该读什么」。一个知识库建议不超过三层，每层使用一致的命名方式。避免按部门建目录，优先按**读者要解决的问题**组织。

### 用标签做横向连接

目录是纵向的，标签是横向的。给文档添加「新手指南」「API」「SOP」等稳定标签，可以把分散在不同目录中的相关内容聚合起来。标签不要超过 3 个，也不要创造同义标签。

### 建立双向链接

在正文中输入 `@` 并选择另一篇文档，就能建立引用。当文档被引用时，原文的「反向链接」区域会显示来源。这比复制链接更有生命力，因为读者可以看见上下文。

## 权限与分享

HappyDays 使用「空间角色 + 文档可见范围」两层权限模型。先由空间角色决定基础能力，再由每篇文档控制更细的可见性。

| 角色 | 查看 | 评论 | 编辑 | 管理 |
| --- | --- | --- | --- | --- |
| **访客** | 仅被分享的文档 | 可选 | — | — |
| **成员** | 空间内文档 | ✓ | ✓ | — |
| **管理员** | 全部文档 | ✓ | ✓ | ✓ |

### 链接分享的三种范围

- **空间内可见：**默认选项，适合绝大多数内部文档。
- **获得链接的人可见：**适合外部合作伙伴，建议同时设置有效期。
- **互联网公开：**仅用于帮助中心、公开规范等确定可以公开的内容。

> [!WARNING]
> **导出不会带走权限**
>
> 拥有编辑权限的成员可以导出 PDF 或 Markdown。导出前请确认接收方可信，尤其是包含客户信息、价格策略或未发布计划的内容。

## 让文档保持可维护

知识库最大的成本不是写作，而是**维护**。下面这些习惯能显著延长一篇文档的保质期：

- 开头注明适用对象、前置条件和最后更新时间
- 把易变的信息（价格、人员、链接）集中放在一处
- 为每篇文档指定唯一维护者，而不是「产品组」
- 用评论和「需改进」反馈建立定期清理机制
- 每季度抽查访问量高但长期未更新的文档

## 快捷键速查

| 动作 | Windows / Linux | macOS |
| --- | --- | --- |
| 全局搜索 | `Ctrl + K` | `⌘ + K` |
| 保存 | `Ctrl + S` | `⌘ + S` |
| 加粗 / 斜体 | `Ctrl + B / I` | `⌘ + B / I` |
| 插入链接 | `Ctrl + K（选中文本）` | `⌘ + K（选中文本）` |

| 发布 | `Ctrl + Enter` | `⌘ + Enter` |
