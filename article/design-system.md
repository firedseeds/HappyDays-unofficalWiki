# 设计规范

*HappyDays 产品的色彩、字体、间距与组件使用准则，让界面保持安静而清晰。*

HappyDays 的设计不追求第一眼的惊艳，而追求**长时间的安静**。我们希望用户把注意力放在内容上，而不是界面上。这份规范记录了我们做取舍时依据的原则。

## 设计原则

### 内容优先

*PRINCIPLE 01*

界面元素应让位于内容。能删掉的装饰就删掉，能降低的对比度就不要抢标题的注意力。

### 清晰胜过聪明

*PRINCIPLE 02*

不要用隐藏手势或模糊文案制造「高级感」。用户第一次使用就能理解，才是真正的效率。

### 一致但不僵化

*PRINCIPLE 03*

相同含义使用相同样式；当场景确实不同，允许有理由的例外，并记录在案。

### 留白也是信息

*PRINCIPLE 04*

空间让关系变得可读。不要把屏幕填满，给阅读和思考留下呼吸的位置。

## 色彩

主色是「HappyDays 绿」，来自植物抽芽的颜色，用于主要操作、选中状态和品牌识别。中性色承担绝大多数界面，避免整页被绿色淹没。

| 色彩 | 色值 |
| --- | --- |
| HappyDays 绿 / Primary | `#0A9B69` |
| 深绿 / Strong | `#06764F` |
| 浅绿 / Soft | `#EAF7F1` |
| 墨色 / Ink | `#1C2822` |
| 次级文字 / Muted | `#5C6B62` |
| 纸白 / Paper | `#FFFFFF` |
| 雾白 / Mist | `#F8FAF8` |
| 边界 / Border | `#E8EDE9` |
| 麦穗 / Accent | `#CF9214` |
| 警示 / Danger | `#C2554D` |

> [!NOTE]
> **对比度是底线**
>
> 正文文本与背景的对比度不低于 4.5:1，大号标题不低于 3:1。绿色只用于点缀和操作，不要用浅绿色承载关键信息文本。

## 字体

界面使用系统无衬线字体，保证中文在不同设备上的一致性。标题通过字重和字距建立层级，不依赖大字号或彩色。

| 示例 | 规格 |
| --- | --- |
| HappyDays | `40 / 750 / -0.045em` |
| 让知识自然生长 | `24 / 700 / -0.03em` |
| 正文保持 1.8 倍行高，适合中文长文阅读。 | `15.5 / 400 / 1.86` |
| 辅助说明使用 11px，保持克制，不抢正文。 | `11 / 400 / 1.6` |

引语与长段落可以偶尔使用衬线字体（宋体）增加节奏变化，但不要用于操作界面或短标签。

## 间距与圆角

我们以 4px 为基本单位，常用间距为 4、8、12、16、24、32、48。不要出现 7px、13px 这样的任意值，除非是光学对齐。

| Token | 值 | 使用场景 |
| --- | --- | --- |
| `space-1` | 4px | 图标与文字、紧凑元素之间 |
| `space-3` | 12px | 卡片内边距、按钮组间距 |
| `space-4` | 16px | 常规卡片内边距、段落间距 |
| `space-6` | 24px | 区块内边距、标题上方间距 |
| `radius-sm` | 7px | 按钮、标签、输入框 |
| `radius-md` | 11px | 卡片、提示框、代码块 |
| `radius-lg` | 16px | 弹窗、大型容器 |

## 组件

组件首先服务于清晰，其次才是美观。一个按钮只能有一个主要动作，次要动作用描边或低饱和背景表达。

> 组件示例：**主要操作** · **次要操作** · **轻量操作**

### 状态必须可感知

悬停、聚焦、禁用、加载中，都要有明确且不突兀的视觉反馈。尤其是键盘聚焦，必须保留可见的焦点环，不能为了「干净」而移除。

### 动效服务于理解

动效用于解释元素从哪里来、到哪里去，时长控制在 150–300ms。不要让页面在每次切换时整体飞入，也不要让用户等待动画结束。

## 可访问性

- 所有操作都可以通过键盘完成，焦点顺序符合视觉顺序
- 图标按钮必须提供可读的 aria-label
- 不仅用颜色表达状态，同时提供文字或图形线索
- 支持系统「减少动态效果」偏好
- 在 200% 缩放下，内容仍然完整可读

*规范不是限制创造力的围墙，而是让不同的人做出协调选择的共同坐标系。有例外时，请说明理由，并更新这份文档。*
